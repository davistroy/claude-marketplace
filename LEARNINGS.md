# Learnings

## Summary

- Three cross-phase findings from this release; all were caught by testing/validation gates before shipping, none reached the release unmitigated.
- Escalation pattern (4.2): a line-budget target collided with a byte-intact protection clause — resolved by separating structural moves (illustrations) from logic edits; pre-authorize that distinction in future item specs when the two could collide.
- Contract-change pattern (3.3): restructuring a shared artifact (shared `.meta.json` → per-agent files) missed two call sites — a whole-file grep for the old artifact name is required on any contract change, not just the primary call sites.
- Syntax-safety pattern (8.2): generated YAML scalars containing `: ` (e.g., "Suggest when:") silently broke plain-scalar parsing across 12 skills — always quote or rephrase such scalars; this class of error is now CI-guarded via the plugin-validate job.
- All three were caught by this plan's own gates (phase testing; 8.6's strict-validate sweep) — the layered Definition-of-Done structure is working as designed.
- Net effect: every escalation and fix is now encoded as either a spec-discipline lesson (4.2, 3.3) or a permanent automated guard (8.2).

- [2026-07-08] 4.2 escalated sonnet→opus: the item's ≤500-line target conflicted with its own byte-intact protection; opus resolved by moving illustration blocks only (470 lines, zero behavior change). Lesson: when a size target and a protection clause can collide, pre-authorize the illustration/logic distinction in the item spec.
- [2026-07-08] 3.3: arch-review per-agent meta rewrite missed the Step 1 shared-meta seed and Step 6 summary — caught by phase testing. Lesson: contract changes need a whole-file grep for the old artifact name.
- [2026-07-08] 8.2: folding trigger text into YAML descriptions introduced unquoted 'Suggest when:' colons that broke plain-scalar parsing in 12 skills — caught by 8.6's strict-validate sweep. Lesson: any generated YAML scalar containing ': ' must be quoted or rephrased; the CI plugin-validate job now guards this class.

## 2026-07-17 — prime backlog (#149–#154) implementation

- **Root cause was one thing, not six:** five of the six backlog issues were verification artifacts that existed but never gated — `update-readme.py --check` exited 0 for any drift, the eval check validated mapping only, the pre-commit hook was uninstalled with a dead `help.md` check inside, and `validate.yml`'s skills-frontmatter branch was dead code. Lesson: a guard that can't fail is worse than none (it launders "unchecked" into a false "checked"). Fix pattern, applied to every gate this run: make it capable of failing → **negative-test it against deliberately-bad input** → only then wire it in. This burned me once already (I'd assumed `update-readme.py` worked), so I negative-tested all of them.
- **Ordering is load-bearing:** repair-before-wire (fix the dead script before adding `--check` to CI, else you ship a green no-op), promote-before-rotate (put D14–D18 in the Decision Log before archiving the entries that hold them, else you delete five decisions), remove-dead-check-before-install (strip the phantom `help.md` check before installing the hook, else every contributor gets three warnings/commit).
- **Two subagent catches beyond the plan spec:** (1) feedback-docx-generator had no `[tool.pytest.ini_options]`, so bare `pytest` in that dir inherited the root config with no `--cov` — the moved coverage floor would never have activated; the agent added the section. (2) The eval structural linter needed to track invocation state *across* follow-on scenarios; a naive "every scenario needs an invocation line" rule would have flagged ~35 legitimate continuation scenarios. Lesson: give implementer subagents the *intent* and let them correct the spec's blind spots.
- **Flaky wall-clock test — root cause deeper than the threshold:** `test_concurrent_generation_overlaps_wall_clock` asserted `concurrent < 2*delay` and flaked on windows-latest. It wasn't just a tight bound — the concurrent run is measured *first* and pays a one-time cold-start cost the serial run doesn't, so under xdist an early/cold-scheduled test collapses the signal. A subtraction fix (`concurrent < serial - delay`) *also* failed cold. The robust fix abandons wall-clock entirely and instruments the actual property (max in-flight coroutines, deterministic under asyncio's single-threaded loop). Lesson: test the property, not a timing proxy for it; reproduce flakes locally *in isolation* (the cold path), not just by re-running CI (E041).
